# DynamicIcon

`@primebrick/ui` — `src/lib/components/dynamic-icon/DynamicIcon.svelte`

## Purpose

Renders any icon by name at runtime — Lucide™ glyphs **and** Primebrick-authored
registries. The icon name is not known at build time (e.g. it comes from module
configuration), so a static import is not possible. `DynamicIcon` resolves the
name through an ordered lookup, then lazy-loads and caches Lucide™ chunks on
first use.

## Origin

**Custom** — fully Primebrick-written. Uses `import.meta.glob` (Vite) and
`@lucide/svelte`. Not vendored from any registry.

## How it works

1. **Resolution order** — every name passes an ordered lookup, and the first
   hit wins. Registries resolve synchronously (no async import):
   `SEMANTIC_ICONS` (self-colored `exec-*` glyphs) → `CUSTOM_ICONS` (authored
   lucide-vocabulary node tuples, e.g. `trash-arrow-up`) → `COMPOSED_ICONS`
   (masked base+overlay mashups) → the Lucide™ glob.
2. A module-level `import.meta.glob` over `@lucide/svelte/dist/icons/*.svelte`
   produces a map of path → lazy import function that Vite can statically
   analyze. This is required because Vite cannot resolve dynamic `import()`
   with template literals.
3. On each name change, an `$effect` calls `loadIcon(name)` which invokes the
   matched loader and caches the resolved component in a `Map`.
4. While the chunk loads, a placeholder `<span>` of the icon's `size` keeps
   layout stable.
5. If the name resolves nowhere, a warning is logged and a dashed `?` marker
   renders at the icon's `size` — a declaration bug stays visible.

## Usage

### Default

```svelte
<DynamicIcon name="package" size={16} />
```

### With a class

```svelte
<DynamicIcon name="settings" size={20} class="text-muted-foreground" />
```

### Driven by module config

```svelte
<DynamicIcon name={module.icon_name} size={18} />
```
